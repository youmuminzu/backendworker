## 修复：--init-ddl 首跑 400 Bad Request

- 根因：`_split_ddl()` 只剔除 `--` 注释行，而 `tables.sql` 文件头用的是 `#` 注释；
  `#` 不是合法 SQL 注释，整段文件头被拼进第一条 CREATE TABLE → D1 返回 400。
  同时 `wrangler d1 execute --file` 也会因 `#` 报错，故 tables.sql 头部注释统一改为 `--`。
- 顺带修的两处：
  1. `_post()` 之前把 400/401/403 也当可重试（raise_for_status 抛 HTTPError 被统一 catch），
     白重试 5 次且丢掉 D1 body。现改为：只有网络异常 + RETRYABLE_STATUS 才退避重试，
     其余 4xx 立即抛 `D1Error` 并带上响应体。
  2. jieba 导入刷屏的 SyntaxWarning（源码非法转义序列）在 `tokenizer.initialize()` 里用
     `warnings.catch_warnings()` 静默。
- 用户本地实际 D1 database_id 是 `5b6eb275-dc01-4fad-bcde-0f99eedd584b`（设计稿里的 f42c3293 已被换掉），
  通过 `.env` 的 `CLOUDFLARE_D1_DATABASE_ID` 覆盖；运行命令 `uv run --env-file .env python -m backendworker.importer`。
